# swift-threefry

Use this package when you need random bits that are the same for the same seed on every machine, and that you can ask for in any order: the value for a seed, a stream and an index, with no earlier value computed first. Start from `Threefry.block(key:counter:)`, the pure function; from `Threefry.Generator`, which reads the same blocks in order and conforms to `Random.Generator` from swift-random and to the standard library's `RandomNumberGenerator`; or from `Threefry.Draws`, unit draws addressed by an item, a stream and an index. It is Threefry-2x64-20 of Salmon, Moraes, Dror and Shaw (*Parallel random numbers: as easy as 1, 2, 3*, SC'11). It is not a cryptographic generator: for secrets, use a platform source that conforms to `Random.Generator`.

## Laws

- Random access is what a counter-based generator is: the values for a (key, stream, index) triple are one call away, and nothing before them is computed. `Threefry.Generator(key:stream:index:)` is the generator for the triple. Give each independent thing its own stream (a particle, a pixel, a task) and draw from it in order: the same triple gives the same values on every machine, whatever was drawn for other streams, in whatever order or on whatever thread.
- `Threefry.block(key:counter:)` with counter `Block(index, stream)` is the triple's 128 bits, as a pure function; its `first` and `second` are the first two values of `next()` on that generator.
- `Threefry.unit(key:stream:index:as:)` is the triple's draw from [0, 1) in one call: the first `unit(as:)` of the generator for the triple, which is the top bits of the block's `first` word as a share of one, `Double(first >> 11) * 0x1p-53` for `Double`.
- `Threefry.unit(of:as:)` is a 64-bit word as a value in [0, 1): its top bits, as many as the type's significand holds, as a share of one, `Double(word >> 11) * 0x1p-53` for `Double`; it is `unit(as:)` of a generator whose next value is the word. `Block.units(as:)` is both words so.
- Two layouts address draws, and each keeps its values. The generator layout, counter `Block(index, stream)`, reads one stream in order and `unit(key:stream:index:as:)` takes one draw per block from it: use it for a sequence, or where the draw for a pair of coordinates is all that is needed. The draws layout, `Threefry.Draws(key:item:stream:)`, addresses a draw by three coordinates and uses both words of a block: draws `2k` and `2k + 1` are the first and second words of the block at counter `Block(item, stream << 32 + k)`. Use it for many things (an item each: a particle, a pixel) that each draw several numbers in several streams (a stream for each use), and read neighbouring draws with `pair(at:as:)`, which costs one block for the two, where `unit(at:as:)` costs one block each.
- The draws layout is the generator layout with the item as the index and `stream << 32 + k` as the stream: draws `2k` and `2k + 1` are the first two `unit(as:)` of `Generator(key:stream:index:)` for those. Streams below 2³² and indices below 2³³ address distinct counter words; beyond them they share one, so index 2³³ of a stream is index 0 of the next.
- A generator holds the block it is reading, so sequential reads compute one block for every 16 bytes, however they are split into `next()`, `byte()` and `fill` calls; creating a generator computes its first block.
- `Threefry.block(key:counter:)` is Threefry-2x64 with 20 rounds, and reproduces the published known-answer vectors. It uses only 64-bit wrapping addition, rotation and exclusive or, so the result is the same on every platform and word size.
- For a fixed key, `block` is a bijection on counters: two different counters never give the same block.
- A `Threefry.Block` reads as 16 `bytes`: `first` then `second`, each little-endian, whatever the byte order of the machine.
- The byte stream of a `Threefry.Generator` is the blocks at counter `(index, stream)` for `index`, `index + 1`, and so on. It depends only on the key, the stream and the position, so any way of splitting a read into `fill`, `byte()` and `next()` calls yields the same bytes. `next()` is the next eight bytes, little-endian.
- A generator created at `index` equals one that has read `16 * index` bytes from the start. `block(at:)` reads any block without moving the generator.
- `fill` never fails, and an empty buffer leaves the generator unchanged.
- The index wraps: after block `UInt64.max` comes block 0, so a stream repeats after 2^68 bytes.
- Equality and hashing compare key, stream and position. Two equal generators produce the same bytes.
